# PHP port roadmap

Updated: 2026-09-30

The project is pre-1.0. The immediate objective is measured compatibility with Swiss Ephemeris 2.10.03, not a nominal count of exported functions.

## Release gates for 0.1.0

- [x] Remove committed Composer dependencies, IDE state and opaque test binaries.
- [x] Add a PHP 8.1–8.5 CI matrix and reproducible release archive.
- [x] Separate a deterministic CI suite from the diagnostic full parity suite.
- [x] Make package, licence, security and contribution metadata explicit.
- [x] Normalize fixture discovery and make the current 209-test full suite pass with the documented data set.
- [ ] Define and publish tolerances per output class: angles, speeds, distances and event times.
- [x] Replace machine-specific PHPUnit fixture paths with `SWEPH_EPHE_DIR` and capability checks.
- [ ] Verify the release candidate against the native C library on a version-pinned corpus.
- [ ] Publish the first tag and register `gutsergut/php-swisseph` on Packagist.

## Correctness workstreams

### 1. Test contract

- Every numerical test records upstream version, flags, time scale, calendar, backend and data-file hashes.
- Angular comparisons use wrap-aware distance.
- Missing data skips an integration test with a reason; it never silently switches the expected backend.
- Returned flags and backend identity are asserted alongside the values.
- Regression fixtures are generated by a separate, version-pinned native reference executable.

### 2. Core calculation parity

Priority order:

1. Sun, Moon, planets and speeds through the analytical Moshier path.
2. Sidereal modes, ayanamsha and true/mean nodes used by Vedic calculations.
3. Houses and angles, including polar behavior.
4. Rise/set/transit and planetary phenomena.
5. Asteroids, fictitious bodies, fixed stars and planetary moons.
6. SWIEPH `.se1` and JPL backends with strict no-fallback assertions.

### 3. Public API stability

- Freeze typed DTOs and error semantics before 1.0.
- Document global state (`swe_set_*`) and isolate it behind explicit context objects where possible.
- Keep C-style wrappers compatible, but implement new application code through the object-oriented facade.
- Add deprecation periods for signature or result-shape changes.

### 4. Framework integrations

- Add dedicated Laravel and Symfony smoke tests against their supported version matrices.
- Keep framework packages optional at runtime.
- Do not let integration code alter the numerical core or global calculation state implicitly.

## Out of scope for the first release

- Claiming complete or bit-identical C compatibility.
- Bundling JPL ephemerides or third-party `.se1` data without verified redistribution terms.
